# 非原版优化记录

本文件记录 Festival 3.1 C++ 原版没有、Rust 移植额外引入的优化。这类优化不作为
移植的一部分写进 `rust-rewrite-plan.md`；计划文档只保留移植本身和为对齐 C++ 语义
所做的修正。

约定：

- 实现级优化不改变任何可观测行为：shift/推拉距离矩阵、走法、死锁判定和
  `solutions.sok` 必须与 C++ 一致，由差分测试或等价性论证保证。
- 启发式优化（搜索顺序、评分或方案选择）可以改变 `solutions.sok`，但必须保持解
  合法：`--validate` 全部重放通过，并在条目中记录 moves/pushes 变化与配对基准。
- 每项优化给出性能数据；原始计时、复现命令与校验和记在 `reference/BASELINE.md`。
- 记录粒度是“一次可独立回滚的实现选择”，性能回归时可直接定位到对应条目。
- 已实测否决的方向统一记录在文末[已否决的优化方案](#已否决的优化方案)；重新尝试前
  先核对对应的“重新评估条件”。

## 2026-10-29 双连通块标注 shift 矩阵

**问题**：`Graph::build` 的 `init_shift` 对每个空格临时放箱，再用一次 BFS 标记四周
玩家所在分量，单次构建是 O(空格数 × BFS)，占 build 时间的 96–98%。XSokoban 1–20
单核 10.4 s 中 1.89 s（15,097 次 build），XSokoban 18 策略 A 2.37 s 中 0.76 s
（6,098 次 build）。

**方案**：每次 build 做一次迭代式 Tarjan 双连通分解（显式栈、按
`level.index_num()` 的 `u16` 数组、遍历所有分量、scratch 挂在 `Graph` 上跨 build
复用）。某格被箱占据后两邻格仍连通，当且仅当两条关联边属于同一个双连通块，于是
shift 边可逐对 O(1) 判定；唯一的调用点 `bfs::mark_connectivities_around_place`
随之删除。

**等价性**：块是 2-连通图或单桥；删去一个顶点后块内其余顶点仍连通，反之若两邻格
在删格后连通，则该路径与两条关联边构成经过该格的环，两条边必同块。墙格、越界格和
`active` 过滤的处理与原实现一致。新增逐格逐方向的暴力 BFS 差分测试（6 个手写盘面 +
300 组随机加墙）覆盖割点、桥、多分量等情形。

**结果**（同日交替配对，1 核）：XSokoban 1–20 9.95 → 8.54 s（−14.5%）；XSokoban
18 策略 A 2.62 → 1.74 s（−33.4%）；Microban 1–155 10.57 → 8.88 s（−16.0%）；
8 核 Microban 13.27 → 11.91 s（−10.3%，受取消时机影响，仅供参考）。临时计时（已
移除）显示残余 `Graph::build` 从 1.89 s 降至约 0.25 s（XSokoban 1–20），约占整体
2–3%。

**验证**：120 个单元测试、clippy/fmt/deny 通过；XSokoban 1–20 为 18,143 moves /
5,466 pushes，Microban 155/155 为 22,486 / 5,920，与基线一致；`solutions.sok`
逐字节相同（仅时间戳），`--validate` 全部重放通过。原始计时与校验和见
[`reference/BASELINE.md`](../reference/BASELINE.md#biconnected-shift-follow-up-2026-10-29)。

**v0.1.1 全量复审**（同日新旧二进制，1 核）：XSokoban 90 关 160.6 → 102.1 s
（−36.4%）。第 1–28、30–90 关的解与步数不变，只有第 29 关从 1277 / 298 变为
705 / 190：该关策略 A 的 75 s 墙钟配额（600 s 的 1/8）在新版内足够解出，旧版与
C++ 则超时后改用后续策略。因此“`solutions.sok` 逐字节相同”只对不受墙钟配额截断的
关卡成立；搜索本身（移位矩阵）的等价性仍由差分测试覆盖。

## 2026-11-02 多规划 forward portfolio

**问题**：反向 packing 通常能找到多个不同的停车方案，原版只使用反向搜索评分最好的
一个。固定预算下不同方案的前向开销差异很大：Microban 153 个 gate 内关卡中，方案 0
的合计扩张为 19,132，逐关最优方案的合计为 10,260，33 关至少有一个更优方案
（例如 Microban 146：6,822 → 175）。

**方案**：仅对 `ForwardWithBases` 且 `box_count <= 12 && index_num() <= 80` 的关卡
启用。按反向评分取前 512 个未死锁扩张，用 `get_parking_plan` 还原方案，与基准方案
去重后最多保留 4 个；每个方案独立执行 verify/reduce/OOP。每个方案在反向 tree 上探测
32 次扩张（显式 `--max-expansions` 时取预算的 1/8，夹在 1..32），探针使用反向
perimeter 的独立 `snapshot()`，避免互相污染；任一方案提前解出即返回。否则按
“最佳节点 `dist_to_targets` ↑ → frontier 最小 `dist_to_targets` ↑ →
`packed_boxes` ↑ → 方案索引”选择，并用剩余预算继续。探针扩张计入该阶段预算。

**结果**（同会话，非交替，1 核）：Microban 6.25 → 4.64 s（−25.7%），扩张
28,724 → 23,755（−17.3%），moves 22,486 → 22,366，pushes 5,920 → 5,926。
XSokoban 98.37 → 98.22 s（−0.2%），扩张 +0.3%：gate 内只有 9 个小关。

**验证**：Microban 155/155、XSokoban 90/90 全部解出并通过 `--validate`；123 个
单元测试与 clippy/fmt 通过。

## 2026-11-02 Hungarian 匹配 advisor

**问题**：FESS 的 advisor 集合没有直接使用“箱到目标”的全局最优分配代价；在部分
关卡上，packed/connectivity 主导的 advisor 会错过更接近完成的子节点。

**方案**：`matching_advisor` 仅对 `Normal | ForwardWithBases` 且
`box_count <= 12 && index_num() <= 80` 启用。用 `compute_match_distance` 计算当前
盘面与每个子节点的分配距离；跳过已扩张、以及 `packed_boxes` 低于父节点的子节点；
取分配距离最小者，平局时用 `is_better_score` 决出。它作为额外 advisor 加入
`is_an_advisor`，不替换原有 advisor。

**结果**（叠加在 portfolio 之上，同会话，1 核）：Microban 4.64 → 4.35 s（−6.4%），
扩张 23,755 → 21,925（−7.7%）；XSokoban 98.22 → 97.46 s（−0.8%，在噪声范围内），
扩张 −0.1%。

## 已否决的优化方案

本节只收录已经实现或做出原型、并经过实测否决的方向。每项都给出当时的证据和
“重新评估条件”；未满足条件前不要重复投入，避免重蹈覆辙。

### 反向完整解复用

**设想**：反向 packing 已经解出时，直接把完整的 pull 宏序列反转成 forward 推步，
跳过前向搜索。

**实测**：在 XSokoban 29、XSokoban 15/16/18、Microban 145/146/153 等关卡上，反向
搜索确实以很少的扩张完成（例如 XSokoban 29 为 19 次），但完整解全部来自
BaseSearch。base 移动会把箱子从初始 base 删除（`to = -1`），反转后的路径不包含这些
箱子；`invert_pull_solution` 在第一个宏上即找不到合法正向路径，所有样本均失败。

**否决原因**：反向路径不保持初始箱子集合，直接反转在语义上就不成立。要修复就必须
重建被删除的箱子并重新规划，代价接近一次新的搜索。

**重新评估条件**：反向阶段改为纯保箱搜索，或已有可靠的反向 base 删箱 → 正向补箱
映射。

### MPDB2 取消 50 对上限

**设想**：去掉每个方向最多 50 个 push/pull 死锁箱对的截断，改为直接索引，以使用
全部两箱模式。

**实测**：对 245 个标准关插桩统计候选数与截断数，push 和 pull 两个方向的
`excluded` 全部为 0；实际表项远小于 50。

**否决原因**：上限从未生效，取消它不会改变任何搜索行为，只会增加存储和代码复杂度。

**重新评估条件**：新语料上重新插桩，确认某关单方向候选超过 50 且截断确实发生。

### 加法式 2-box PDB

**设想**：为箱对建立精确推距离表，把若干互不相交箱对的距离相加，作为比
Hungarian 单箱分配更强的下界或 advisor。

**实测**（Microban 155 关原型）：按目标对建表后，做“箱对/目标对都不相交”的贪心
加和，在 9/155 关得到的值超过真实解推数（例如 Microban 146 为 62，而实际解为
44 推），因此不是合法下界；合法的单对最大距离仅在 8/155 关比 Hungarian 分配更紧。
建表在 Microban 146 约 0.9 ms；对秒级关卡可忽略，但对毫秒级小关占比不可忽视。

**否决原因**：目标可互换，朴素的加和分解不保证与真实目标分配一致；合法形式又与
现有 Hungarian 分配高度重叠，且建表成本相对于小关求解时间过高。

**重新评估条件**：能对某类关卡给出可证明合法的目标划分，或找到不必枚举目标对的
模式构造，并证明其增量收益。
