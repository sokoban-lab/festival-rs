# festival-rs 0.1.0 XSokoban 基准测试

本文记录 **festival-rs 0.1.0** 在 XSokoban 全部 90 关上的单核耗时与峰值内存，
并与上游 Festival 3.1 C++（下文简称 C++）做同机对比。测试日期为 2026-10-29。

## 结论

在 600 秒/关、单核、默认八策略调度下，Rust 与 C++ 都解出 **90/90**。
以两轮交错的批量运行（每轮一个进程跑完 90 关）作为端到端结果，按每边两轮最好成绩比较：

| 指标                             | festival-rs 0.1.0 |  festival-cpp 3.1 |    Rust / C++ |
| -------------------------------- | ----------------: | ----------------: | ------------: |
| 解出关卡                         |             90/90 |             90/90 |             — |
| 批量总耗时（两轮最好）           |         176.736 s |         194.512 s |     **0.909** |
| 批量总耗时（两轮范围）           | 176.736–185.699 s | 194.512–197.858 s |   0.893–0.955 |
| 批量峰值工作集（两轮最好）       |          339.6 MB |          870.8 MB |     **0.390** |
| 单关峰值工作集最大值（第 29 关） |          290.4 MB |          843.8 MB |     **0.344** |
| 总步数 / 推动数                  |   94,231 / 28,709 |   94,245 / 28,709 | 99.99% / 100% |
| 解回放                           |             90/90 |             90/90 |             — |
| 逐关独立进程累计耗时             |         194.554 s |         212.973 s |         0.914 |

批量数字是端到端比较。逐关累计把每一关都放在新进程里，包含重复的进程启动和
一次性分配成本（C++ 每进程约 700 MB 的固定工作集），因此短关卡的比值会明显偏向
Rust；逐关表主要用于定位单关差异，不应把 0.914 当作稳定状态下的吞吐比。两轮批量
运行的主机漂移约 5%，因此表中同时给出两轮范围和最好成绩。

## 测量方法

- **预算与策略**：每关 600 秒、单核，不指定策略（Rust 的 `--alg` / C++ 的 `-alg`），
  即两边的默认八策略调度；C++ 用 `-from/-to` 选择关卡。
- **亲和性**：两个二进制在进程启动后立即固定到逻辑 CPU 0（i9-14900HX 的 P-core）；
  未固定时 P/E-core 迁移足以让单核比值漂移约 2 倍。
- **逐关数据**：每关启动一个全新进程。耗时是 Stopwatch 包住进程启动到退出的墙钟时间，
  包含进程启动、关卡预处理、一次性缓存/树分配、搜索和写文件；内存是操作系统报告的
  峰值工作集（20 ms 采样加进程退出时的 `PeakWorkingSet64`）。
- **批量数据**：每轮一个进程连续跑完 90 关，同样单核、600 秒/关，记录端到端墙钟和进程峰值。
  共两轮，第一轮 Rust→C++，第二轮 C++→Rust；摘要按每边两轮最好成绩给出，并列出两轮范围。
- **交错顺序**：同一轮的 Rust/C++ 按关卡奇偶交替先后，两轮批量运行交换先后，且两套测量不并发运行，
  以减小主机随时间的漂移。
- **内存单位**：MB = 1048576 字节，与 `reference/BASELINE.md` 的记法一致。

批量运行明细：

| 轮次 | 顺序 | Rust 耗时 | C++ 耗时 | 耗时 R/C | Rust 峰值 | C++ 峰值 |
|---|---|---:|---:|---:|---:|---:|
| 1 | Rust→C++ | 185.699 s | 194.512 s | 0.955 | 339.6 MB | 870.8 MB |
| 2 | C++→Rust | 176.736 s | 197.858 s | 0.893 | 341.6 MB | 874.6 MB |
| 两轮最好 | — | 176.736 s | 194.512 s | 0.909 | 339.6 MB | 870.8 MB |

两轮都解出 90/90，步数/推动总量分别为 Rust 94,231/28,709 和 C++ 94,245/28,709。

逐关耗时含固定启动成本，因此第 1–9 关这类一秒内完成的关卡，C++ 的约 700 MB
初始化和进程启动会放大差距；真正反映稳定吞吐的是批量行。

## 说明

- **Rust 更快的关卡**：逐关耗时比值中位数 0.663（均值 0.688），90 关中有 86 关 Rust 更快；
  C++ 更快的 4 关是 10、16、66、75，最大差距在第 66 关（Rust 7.739 s，C++ 6.481 s，1.194×）。
  两轮批量比值为 0.893 和 0.955，最好成绩比 0.909；逐关表中偏低的短关卡比值主要来自
  C++ 每进程的固定启动成本。
- **第 29 关是唯一的时间边界关卡**：Rust 112.366 s，C++ 116.767 s，两者都在 600 秒内解出。
  在更小的 120 秒预算下，非固定 CPU 的预跑曾出现 Rust 超时，因此正式数据使用 600 秒。
- **内存**：逐关 Rust 峰值 148.7–290.4 MB，C++ 峰值 709.8–843.8 MB，内存比值中位数 0.255；
  最坏情况都在第 29 关，Rust/C++ 为 0.344。批量运行因跨关分配保留，两轮峰值为
  Rust 339.6–341.6 MB、C++ 870.8–874.6 MB，比值 0.390–0.391。
  C++ 的固定成本主要来自进程级死锁缓存和搜索树；Rust 的缓存按 worker 分配，单核运行时更小。
- **解质量**：逐关两边都是 94,231 步 / 28,709 推动，每一关完全相同；批量运行只有第 81 关
  不同（Rust 617 步，C++ 631 步，推动数相同），总量为 94,231/28,709 对 94,245/28,709。
  全部批量解和 180 个逐关解都用独立 LURD 回放验证，0 个非法解。

## 复现

构建：

```sh
cargo build --release -p festival-cli
scripts/build_cpp_ref.sh
sha256sum -c levels/corpus/xsokoban.sok.sha256
```

批量对比（单核、600 秒/关）：

```sh
mkdir -p out/rust out/cpp
target/release/festival-rs.exe levels/corpus/xsokoban.sok \
    --level 1..90 --time 600 --cores 1 --out-dir out/rust
target/festival-cpp.exe levels/corpus/xsokoban.sok \
    -from 1 -to 90 -time 600 -cores 1 -out_dir out/cpp
```

重复一轮并交换两个求解器的先后，得到本文的第二个批量样本。

单关峰值内存用 `scripts/process_rss.ps1`，例如第 29 关：

```sh
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/process_rss.ps1 \
  -Out out/rss-rust-29.log -Exe target/release/festival-rs.exe \
  -ArgList "levels/corpus/xsokoban.sok|--level|29|--time|600|--cores|1|--out-dir|out/rust-29"

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/process_rss.ps1 \
  -Out out/rss-cpp-29.log -Exe target/festival-cpp.exe \
  -ArgList "levels/corpus/xsokoban.sok|-from|29|-to|29|-time|600|-cores|1|-out_dir|out/cpp-29"
```

表中的墙钟时间是在同样的启动/等待路径上额外用 Stopwatch 记录的；`process_rss.ps1`
本身只输出峰值和退出码。单核计时请用 `start /affinity 1`（或等价的亲和性设置）固定到 CPU 0。

回放：

```sh
target/release/festival-bench.exe verify-solutions \
  levels/corpus/xsokoban.sok out/rust/solutions.sok
target/release/festival-bench.exe verify-solutions \
  levels/corpus/xsokoban.sok out/cpp/solutions.sok
```
